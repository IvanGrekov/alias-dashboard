# Alias Host App — контекст для AI-агентів

Це інструмент ведучого для гри **Alias**: підготовка гравців і слів, ведення ходів з таймером,
рахунок, журнал подій, фінальні результати. Документ дає повний контекст для роботи з кодом
у новому чаті без попередньої історії.

## Стек і запуск

* Vanilla HTML + CSS + JavaScript. Без збірки, залежностей, фреймворків і сервера.
* Запуск: відкрити `index.html` у браузері.
* Усі дані живуть у localStorage браузера; мережевих викликів немає.

## Файли

| Файл         | Призначення                                                          |
| ------------ | -------------------------------------------------------------------- |
| `index.html` | Розмітка двох екранів: setup (Step 1–2) і гра                        |
| `app.js`     | Уся логіка: стан, рендер, таймери, persistence, генерація промпта    |
| `styles.css` | Усі стилі                                                            |
| `README.md`  | Документація для людей; містить копію шаблону промпта                |

## Архітектура `app.js`

* Один глобальний обʼєкт `state` (фабрика `createEmptyGameState()`), один `CONFIG` з усіма
  константами: межі гравців (2–6) і раундів (1–3), `wordsPerPlayerPerRound: 14`,
  `mainSeconds: 120`, `extraSeconds: 60`, палітри кольорів та іконок.
* Стейт-машина через `state.phase`:
  `setup` → `between-turns` → `running` → (`extra`) → `between-turns` / `round-ended` → … → `game-ended`.
* Рендер декларативний: будь-яка мутація стану завершується викликом `renderGame()`,
  який перемальовує scoreboard, порядок ходів, лог, головну панель і **зберігає стан** (`saveState`).
* Обробники подій навішуються заново після кожного рендеру панелі (innerHTML-підхід).

### Таймер

* Зворотний відлік від wall-clock дедлайну (`timerDeadline = Date.now() + seconds * 1000`),
  interval 250 мс — лише тригер перемалювання. Це захищає від дрейфу `setInterval`
  і тротлінгу фонових вкладок.
* `state.timeLeft` — секунди, що залишились (персистяться, використовуються для паузи/resume/undo).
* Пауза (`state.isPaused`) доступна лише у фазі `running`; на паузі блокуються кнопки
  відгадувачів і Skip word, таймер зупинено.

### Persistence (localStorage)

* `STORAGE_KEY` (`alias-host-app-state-v1`) — повний стан гри, пишеться при кожному рендері
  та зміні секунди таймера. Відновлюється в `restoreSavedState()` при завантаженні:
  перерваний `running`-хід відновлюється **на паузі**, `extra` — з автозапуском таймера,
  завершена гра — на фінальному екрані.
* Збережений стан проходить `isValidSavedState()` (фази з allowlist, форма гравців,
  `order` як перестановка id, лог — масив рядків, числові індекси). Невалідне — видаляється,
  застосунок відкривається на setup.
* `SETUP_DRAFT_KEY` (`alias-host-app-setup-v1`) — чернетка Step 1–2 (імена, раунди, слова),
  пишеться при кожному введенні, відновлюється при завантаженні.
* Обидва ключі очищуються **лише** при Start new game / Clear setup (`resetSetup`).

### Undo

* `takeSnapshot()` перед кожним нарахуванням балів → `state.lastScoreSnapshot`.
* Undo відновлює рахунок, фазу, слово, залишок часу та лог.
* Снапшот живе до старту наступного ходу, тому кнопка Undo доступна і після завершення ходу:
  у панелях between-turns, round-ended та на фінальному екрані (`renderUndoButtonIfAvailable`).
* Якщо гра на паузі, undo не перезапускає таймер.

### Промпт для генерації слів

* `buildWordsPrompt(playerCount, roundsCount)` генерує промпт для AI-асистента, який створює
  всі набори слів. Усі числа й переліки виводяться з `CONFIG` і параметрів — нічого не хардкодиться.
* Промпт показується в `<details>` на екрані слів, копіюється кнопкою Copy prompt
  (Clipboard API з fallback на `execCommand`).
* **При зміні тексту промпта — оновити його копію в `README.md`.**

## Правила гри (стисло)

* 2–6 гравців, 1–3 раунди. Типи раундів (константа `ROUND_DESCRIPTIONS` — єдине джерело
  для легенди й заголовків): 1 — українські слова, 2 — тематичні українські, 3 — англійські.
* Рівно **14 слів** на гравця в кожному раунді, вводяться одним рядком
  (роздільники: кома, крапка, крапка з комою, новий рядок — `parseWords`).
* Слова та імена унікальні в межах гри; порівняння через `normalizeForDuplicateCheck`
  (NFC, апострофи, нижній регістр uk-UA).
* Порядок гравців — випадковий, визначається один раз на гру; кожен гравець отримує
  унікальні іконку та колір.
* Хід: Start turn → 2:00 основного часу. Відгадане слово: пояснювач **+2**, перший
  відгадувач **+1**, перехід до наступного слова. Після 2:00 — `confirm` про додаткову
  хвилину (1:00): у ній можна завершити лише поточне слово; відгадали — бали і кінець ходу,
  ні — 0 балів і кінець ходу.
* Службові кнопки під час ходу: Pause/Resume (лише основний час), Skip word (0 балів,
  наступне слово; останнє слово — кінець ходу), Undo last score, End turn (слово не
  зараховується), Finish game (дострокове завершення всієї гри з підтвердженням →
  фінальний екран).
* Наступний хід/раунд ніколи не стартує автоматично — лише кнопками Start turn / Start new round.
* Фінал: рахунок, місця з урахуванням нічиїх, переможець/переможці. Start new game — повний
  скидання (включно з localStorage).
* Лог: уся історія подій, найновіші зверху, гравці відображаються з іконкою та кольором.

## Конвенції та інваріанти

* **XSS-дисципліна**: будь-який користувацький рядок (імена, слова) перед потраплянням
  в `innerHTML` проходить `escapeHtml`. `state.log` зберігає **готовий HTML**, який можна
  будувати лише через `logPlayer()` + `escapeHtml()` — нові записи в лог додавати тільки так.
* Кількість слів у наборі — лише через `CONFIG.wordsPerPlayerPerRound`, не хардкодити «14».
* Мова UI: тексти українською, назви кнопок англійською (Start turn, Skip word, Finish game…).
* Дизайн: стилі через CSS-змінні в `:root`, наявні класи кнопок
  (`primary-btn` / `secondary-btn` / `danger-btn` / `ghost-btn`) — перевикористовувати.
* Валідація помилок setup показується через `showValidationSummary`; при натисканні
  Start game сторінка скролиться до списку помилок.

## Відомі обмеження (кандидати на покращення)

* Лог зберігається в localStorage як HTML-рядки — підроблене сховище дає self-XSS;
  план: перейти на структуровані записи (`{type, playerId, word}`) і рендерити з них.
* Дві вкладки з однією грою перезаписують стан одна одної (last write wins).
* `document.execCommand("copy")` як fallback — deprecated, але робочий.
